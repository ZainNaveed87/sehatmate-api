# Phase 2 implementation plan

Preserve baselines Flutter f5a6627 and backend c55d7f7, plus every pre-existing local change recorded in the task workspace's phase_2_preexisting_baseline.json. No staging, commits, deployments, provider changes or database execution.

1. Extend the existing Agent with optional `clientContext.ui` and response `uiPlan`. Keep legacy screen context and response fields compatible. UI descriptions are untrusted UI-only evidence; authoritative patient facts still come from registered backend tools.
2. Add closed, bounded server validation for semantic snapshots and operations. Snapshot: `{screenId, route, version, focusedSectionId, entities, targets, actions}`. Targets: `{id, kind, label, selected?}`. Actions: `{id, kind, targetId}`. Plan: `{id, screenId, version, operations:[{actionId,targetId,args}]}`. Version is a nonempty opaque screen-generation string. Registered route values use existing Agent navigation target IDs. No arbitrary routes, targets, methods or coordinates. Limit targets/actions to 20, operations to 4 and UI snapshot to 4096 bytes.
3. Add Flutter registry, semantic anchors/highlights and deterministic executor. Executor fences screen/version/account before and after every awaited operation, rejects unavailable capabilities, deduplicates plan operations, and applies server-derived risk tiers. Reuse actual screen callbacks. Existing Reality Check callbacks persist answers: selection/advance must therefore request explicit confirmation; do not label these as temporary writes. Keep draft workflows and current steps account scoped and resumable. Provide undo only where it is genuinely safe.
4. Layer a global typing companion over the existing app-owned Agent/voice state. Keep the underlying route mounted and navigable. Publish current semantic context through the existing typing request and an authenticated, expiring context sync endpoint, allowing unchanged Worker turns to use the same backend planner.
5. Add structured, account-scoped, revocable MySQL memory and meaningful UI action receipts with repeatable migrations; do not run migrations. Memory is bounded/relevant, distinguishes confirmed/preference/inferred information, requires explicit evidence/confirmation, and supersedes corrections. Register authenticated namespaced endpoints and integrate bounded memory into the existing planner.
6. Add deterministic operational conflict detection from verified backend tool results and confirmed relevant constraints. Suggestions are selected from registered non-clinical resolutions. No inferred medical facts or executable treatment changes.
7. Wire Reality Check as the complete reference adapter, then supported screen sections and the Care Gap navigation/highlight reference through reusable adapters. Report actual coverage rather than claiming every control is actionable.
8. Test validation, stale/unknown/duplicate operations, confirmation, memory isolation/supersession, verified conflicts, text/voice output parity, actual widget execution, workflow lifecycle, accessibility, existing voice/language behavior and existing backend regressions. Run Flutter full tests/analyze, both diff checks, and compare baseline hashes. Record live-provider/database/device blockers explicitly.

Implementation ownership: backend UI protocol/planner/core integration in the primary task; isolated Flutter host/registry/adapters/tests and backend memory/conflict/store/routes/tests can proceed independently against the contracts above. Review interfaces and run integrated regressions before reporting.
